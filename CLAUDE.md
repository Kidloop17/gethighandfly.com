# Get High And Fly — инструкции для Claude Code

## Контекст
GHAF — ежегодные соревнования по кайтсерфингу (big air). Одностраничный лендинг,
который переиспользуется каждый год: новый сезон = один файл контента, не правки кода.
Аудитория: райдеры, зрители, партнёры, волонтёры. Три языка: en, ru, vi.
Полная спецификация: `docs/SPEC.md`

## Стек
- **Astro** `output: 'static'`, TypeScript strict
- **Стили**: CSS-переменные + Astro scoped styles. Без Tailwind, без UI-китов.
- **Контент**: Astro Content Collections (`src/content/`)
- **Изображения**: `astro:assets` → AVIF/WebP
- **Галерея**: PhotoSwipe
- **Бэкенд форм**: Node + Fastify + SQLite (`/server/`), отдельный сервис на том же VPS
- **Хостинг**: VPS, Caddy (авто-HTTPS, Brotli, HTTP/2)
- **CI/CD**: GitHub Actions → build → rsync → reload

## Команды
```bash
npm install              # зависимости Astro-части
npm run dev              # dev http://localhost:4321
npm run build            # сборка в dist/
npm run preview          # предпросмотр dist/
cd server && npm install # зависимости бэкенда (Фаза 3)
```

## Железные правила
- Весь UI-текст — только в `src/i18n/{ru,en,vi}.json`. Строки в разметке — ошибка.
- Весь контент — только в `src/content/`. Хардкод данных в компонентах — ошибка.
- Все CSS-токены (цвет, типографика, отступы) — только в `src/styles/tokens.css`.
- Astro Islands — только там, где нужна интерактивность: галерея, форма, архив-табы, переключатель языка.
- React/Vue/Svelte — не добавлять без явного согласования.
- Не начинать следующую фазу без принятия текущей (см. `docs/BACKLOG.md`).
- `dist/` — артефакт, не коммитить. Секреты — в `.env`, не в git.
- Production deploy — только с подтверждения владельца.

## Как работать
- Двигаться по фазам из `docs/BACKLOG.md`, не перескакивать.
- Нет данных (даты, имена, цифры) → ставить `TODO:` и спрашивать, не выдумывать.
- Перед коммитом: `npm run build` без ошибок.
- Добавление зависимости — с объяснением зачем.
- В конце каждой фазы: короткий отчёт, дождаться подтверждения.
- В конце сессии: обновить `HANDOFF.md`.

## Документация проекта
- `HANDOFF.md` — **читать в начале сессии**; обновлять в конце
- `docs/SPEC.md` — перед задачей по логике, секциям, i18n
- `docs/ARCHITECTURE.md` — при изменении структуры, потоков данных, i18n-роутинга
- `docs/DECISIONS.md` — перед изменением ключевого решения; **дополнять** при новых ADR
- `docs/BACKLOG.md` — чтобы понять что сделано и что дальше
